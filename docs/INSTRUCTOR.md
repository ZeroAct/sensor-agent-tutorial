## 진행자가 되는 방식

오늘 권위는 “베어링 결함주파수”가 아니라 **도구와 언어를 설계하는 일**에 둡니다.

말해도 되는 것

- LLM은 센서에 직접 연결되어 있지 않다
- MCP는 도구 호출의 계약이다
- Skill은 그 계약을 현장에서 어떻게 쓰는지 적은 Markdown이다
- 숫자는 도구에서 온다
- 조회만으로 끝나는 일에는 에이전트가 과할 수 있다
- 더미의 변경 도구는 수업용 샌드박스다. 실설비 기동/정지는 모델에게 주지 않는다

말하지 말 것

- “RMS 7.0이면 베어링이 80% 남았다”
- “이 모델이 예지보전을 대체한다”
- FFT, 엔벨로프, ISO 등급을 즉석 강의로 확장
- 수강생 키를 채팅창이나 슬라이드에 붙여 넣고 진행

모르면 “오늘은 더미 임계값입니다. 현장 기준은 설비마다 다릅니다.”가 정답입니다.

## 블록별 말하기 포인트

### 이론 1 — 예지보전 개요 (~8분)

**목표:** 사후/예방/예지를 **한 장**으로 구분하고, AI를 ‘고치는 주체’가 아니라 **루프의 설명자**로 위치시킨다.

#### 말하기 포인트 (분 배분)

1. **(2분) 세 칸 칠판**
   - 사후: 멈춘 뒤 고친다 → 단순, 다운타임·비용 큼
   - 예방: 달력으로 간다 → 과보전 + 미보전 동시 발생
   - 예지: 상태 신호가 나빠지면 간다 → **신호 + 판단 규칙**이 필요
2. **(3분) 예지의 한 문장**
   - “고장이 나기 전에, 상태 신호를 보고, **사람이 개입할 시간을 버는** 일.”
   - AI는 가운데가 아니라 루프 **오른쪽**: 감지 → 기록 → 조회 → 설명 → **결정**
   - 오늘 더미에는 변경 도구가 있다. **실설비의 기동/정지를 모델에게 준 것이 아니다.**
3. **(2분) 현업 언어 번역**
   - “스마트 공장 = AI가 알아서”가 아니라 “측정 → 규칙 → 사람”
   - 오늘 숫자 = 학습용 더미. 실제 진단 절차 아님
4. **(1분) 체크포인트**

#### 비유

- **건강검진**: 사후=응급실, 예방=매년 같은 날 피검사, 예지=혈압이 계속 오르면 의사에게 예약
- **네비게이션**: 센서=GPS, 챗봇=길 안내 멘트. 네비가 핸들을 돌리지 않음. 오늘은 더미 핸들이 열려 있을 뿐.

#### must-say

- 예지보전 = 감지→판단→**사람 조치** 루프
- AI/챗봇은 조치자가 아님
- 오늘은 더미 데이터; 현장 기준으로 쓰지 말 것

#### must-not-say

- “이 모델이 예지보전을 대체한다”
- 잔여수명(%), 베어링 결함주파수, ISO 등급 즉석 강의
- “AI가 설비를 고친다”

#### 체크포인트

1. “예방보전과 예지보전의 결정적 차이는?” → **달력 vs 상태 신호**
2. “실설비에서 모델에게 기동/정지를 주면?” → **과하고 위험. 오늘은 더미 샌드박스.**

### 이론 2 — 센서 이상 시나리오 (~10분)

**목표:** 가상 플랜트 스토리로 ‘이상(anomaly)’을 현업 언어에 붙이고, 오늘 이상은 **단순 임계값(threshold)** 임을 고정한다.

#### 말하기 포인트 (분 배분)

1. **(2분) 무대 세팅**
   - 가상 공장 top-down: 센서 **10개**. 주인공은 여전히 `pump-a-de`
   - 조연으로 펌프 NDE, 팬 B, 압축기, 컨베이어, 믹서, 프레스, 냉각탑이 같은 지도에 있다
   - 실습 전에 브라우저에서 `http://localhost:8000` 평면도를 한 번 보여 준다
2. **(3분) RMS를 ‘크기 한 숫자’로만**
   - 정상 ≈ 2 mm/s (더미)
   - 경고 4.5 / 이상 7.0 = **수업용 숫자**, 현장 기준 아님
   - “왜 RMS?” → “한 숫자로 크기를 말하려고. 주파수 분석은 오늘 범위 밖.”
3. **(3분) 이상 = 임계값 초과 (딥러닝 아님)**
   - 약 10초마다 스파이크, 같은 센서 3회면 해당 설비 트립
   - 현업 언어: RMS↑ = “상태가 나빠지고 있다” (원인 단정 금지)
   - normal / warning / anomaly 읽는 법 (안전 인증 아님)
4. **(2분) 체크 + 실습 예고**
   - 나중에 챗봇 답이 `/demo/sensors` JSON과 다르면 → 모델이 추측한 것

#### 비유

- **체온계**: 38.5°C는 ‘뜨겁다’는 신호. 원인 진단은 체온계가 하지 않음
- **과속 카메라**: 제한 초과 = 이벤트. 왜 밟았는지는 모름
- **신호등**: 노랑=warning, 빨강=anomaly (오늘은 더미일 수 있음)

#### must-say

- 오늘 이상 = **코드의 임계값(threshold)**. 모델이 탐지한 것 아님
- 숫자는 수업용; 현장 기준은 설비마다 다름
- 원인(베어링/언밸런스 등)을 지어내지 말 것

#### must-not-say

- “RMS 7.0이면 베어링이 80% 남았다”
- FFT, 엔벨로프, 결함주파수 확장 강의
- 실설비 정비 절차처럼 말하기

#### 체크포인트

1. “오늘 실습의 anomaly는 누가/무엇이 만드나?” → **더미 센서의 임계값 규칙** (LLM 아님)
2. “warning인데 추세 도구가 없으면 Skill이 뭐라고 해야 하나?” → **없다 / 한계를 말할 것**

### 이론 3 — 챗봇 + MCP + Skills (~15분)

**목표:** ‘챗봇만’의 한계 → MCP(조회 vs 변경) → Skill → **에이전트가 필요한 순간**. MQTT는 오늘 없음.

#### 말하기 포인트 (분 배분)

1. **(4분) 막히는 지점 1 — 챗봇만**
   - LLM = 어제 인터넷 지식. **지금 펌프 값이 아님**
   - 비유: 도서관 사서에게 “우리 공장 펌프 지금 진동?” → 책만 있고 현장 계측기 없음
2. **(5분) 막히는 지점 2 — MCP**
   - MCP = 모델이 부를 수 있는 **도구의 표준 연결/계약**
   - 오늘 도구는 두 층:
     - 조회: `list_assets`, `list_sensors`, `get_vibration_reading`, `get_recent_events`
     - 변경(더미): `request_fix`(화면 수락), `set_asset_power`, `fail_asset`, `replace_asset`
   - 설비 인스턴스와 센서는 다르다. `pump-a`를 끄면 `pump-a-de`가 offline이 된다
   - 데이터 경로: 더미 생성기 + SQLite → MCP stdio → Claude Desktop
3. **(4분) 막히는 지점 3 — Skills**
   - 도구가 있어도 모델은 대충 요약 / 없는 ID / **말 안 한 펌프를 끔**
   - Skill = 도구를 *어떻게* 쓸지 적은 **Markdown 플레이북**
   - 변경 도구가 열려 있어서 Skill이 더 중요해진다
4. **(2분) 체크**

#### must-say

- LLM은 플랜트에 직접 연결되지 않음
- 조회와 변경은 권한이 다르다
- 한 숫자 보기 ≠ 에이전트가 필요한 일

#### 체크포인트

1. “챗봇만으로 부족한 이유는?” → **현재 현장 값에 연결되어 있지 않음**
2. “설비 ID와 센서 ID 차이는?” → **인스턴스 vs 그 위의 측정점**

---

### 이론 4 — Skill / MCP 설계 원칙 (~17분, 가장 깊게) ★핵심

**목표:** 작은 도구, 그라운딩, 그리고 **언제 에이전트이고 언제 과한지**. Skill 화면 공유.

#### 말하기 포인트 (분 배분)

1. **(3분) Skill 4칸**
   - 역할 / 언제 쓰나 / 절차 / 출력
   - **화면 공유:** [`playground/skills/vibration-pdm.md`](../playground/skills/vibration-pdm.md)
2. **(3분) 도구는 동사+명사, 층이 나뉜다**
   - 조회와 변경을 한 도구에 섞지 말 것 (`do_everything` 금지)
   - 좋은 예: `get_vibration_reading` vs `fail_asset`
3. **(4분) 에이전트가 맞는 때 / 과한 때 ★오늘 핵심**
   - **맞다:** 목록 → 값 → 고장 → 교체처럼 순서가 있는 일. 지도만으로 안 끝남
   - **과하다:** RMS 하나 보기, 새로고침. 그건 공장 화면/`curl`이면 됨
   - **실설비에서 과하고 위험:** 기동/정지/교체를 모델에게 맡김. 오늘은 더미라 버튼을 열어 둔 것
   - 비유: 계산기 vs 비서. 숫자 하나면 계산기. 여러 서류와 승인이면 비서(+절차서)
4. **(3분) 그라운딩**
   - 도구 전 숫자 금지. 실패 시 “못 읽었다”. curl이 정답지
5. **(2분) 안티패턴 + 회고 씨앗**
   - 만능 도구 / 키를 프롬프트에 / 말 안 한 펌프를 끔 / 더미를 현장으로
   - “우리 팀에 챗봇을 붙인다면, **에이전트에게 맡기지 않을** 일은 ○○이다.”

#### must-say

- 에이전트 = 도구를 **이을** 때. 대시보드로 되는 일에 붙이면 과함
- 더미 변경 도구는 체감용. 실설비 허가 아님
- 실패 시 추정 금지

#### 체크포인트

1. “에이전트가 과한 질문 예시는?” → **지금 RMS만 알려줘 / 지도 봐**
2. “도구가 실패했을 때 좋은 답은?” → **못 읽었다. 가짜 RMS 금지**

## 실습 진행 (50분)

### 환경 (15분)

기동은 [README](../README.md). 프로젝터에 Claude Desktop 재시작만 보여 줍니다.

성공 신호

- 공장 http://localhost:8000
- Claude Desktop에 **dummy-plant**

막힌 사람: `uv --version`, Claude 재시작, 포트 충돌만 본다. 디버깅에 10분을 쓰지 않습니다.

### 연결 (15분)

`uv run claude-config`가 dummy-plant를 Claude 설정에 넣습니다. 수강생이 JSON을 손으로 고치지 않게 합니다.

1. Claude Desktop을 트레이까지 종료한 뒤 다시 연다
2. Settings → Developer 에서 **dummy-plant** 확인
3. Skill Markdown을 프로젝트 지시 또는 첫 메시지에 그대로 붙여 넣는다
   로컬 Python Tool을 만들지 말라고 한 번 더 말한다

이론에서 “MCP는 설정 파일에 서버를 적는 일”은 한 줄로만 보여 줍니다.

### 질문 (10분)

수강생이 직접 타이핑하게 합니다.

1. `지금 플랜트에 설비와 진동 센서가 뭐가 있나요?`
2. `pump-a-de 최신 값 알려 주세요. 숫자와 시각을 그대로.`
3. `최근 이벤트를 짧게 인용해 주세요.`
4. (시간 남으면) `더미에서 pump-a를 고장 내고 교체하세요. 새 시리얼을 인용하고, 실설비 승인이 아니라고 적으세요.`

좋은 답의 조건

- 설비 ID(`pump-a`)와 센서 ID(`pump-a-de`)를 섞지 않는다
- RMS가 `/demo/sensors`와 크게 다르지 않다
- 변경을 했으면 도구로 다시 확인한다
- “실설비 정비 승인” 문장이 없다

### 해석과 리스크 (10분)

같은 답을 현장 언어로 다시 읽습니다.

- normal → 지금은 수업용 기준에서 평온
- warning → 추세를 더 보자 (오늘 실습은 추세 도구가 없음 → Skill이 한계를 말해야 함)
- anomaly → 값이 튀었다. **더미 스파이크일 수 있다**고 정직하게

리스크 두 개를 경험과 연결합니다.

- dummy-plant가 안 보이는 사람 → 창피하지 않다. 트레이까지 종료. 그래도 안 되면 `curl` JSON
- Desktop 설치가 막힌 사람 → 짝/진행자 화면. 공장 지도는 계정 없이 됨

| 증상 | 원인 후보 | 진행자가 할 일 |

2. `/health`가 ok
3. Skill을 읽고 “에이전트가 과한 일 / 필요한 일”을 한 문장으로 말할 수 있다

**Q. 실제 공장 버스/PLC에 그냥 붙이면 되나요?**

**Q. 이상 탐지를 모델이 하면 안 되나요?**  
A. 할 수는 있습니다. 오늘은 의도적으로 임계값을 코드에 두었습니다. 모델은 설명자입니다.

**Q. Skill을 영어로 써야 하나요?**

A. 가능하지만 오늘 범위 밖입니다. 운영 팀이 파이썬을 안 고쳐도 되게 Markdown으로 제한했습니다.

**Q. Claude Desktop이 없으면요?**  
A. 짝을 이루거나 진행자 화면을 봅니다. JSON 데모로 목표의 80%는 전달됩니다.
